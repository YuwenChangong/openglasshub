## Existing Importer And Precedence

The older schema-v1 CLI is local-only. This channel does not remove or bypass
that guard. The accepted canonical renderer is offline and insert-only, but did
not itself provide Production authorization, transaction lifecycle, or dry-run
reconciliation. This channel supplies those boundaries around the same SQL.

Precedence is the approved migration packet's insert-only rule, not YAML wins:

- Existing rows and publication decisions stay untouched.
- Already consistent identities require zero new rows.
- Absent identity is eligible for insertion, within reviewed entity ceilings.
- A matching device with NULL schema_type can receive only its approved type.
- Existing non-NULL type, brand, or incompatible definition blocks import.
- Existing administrator facts/presentation and richer existing facts remain
  unchanged. YAML differences are classified, never applied as fact updates.
- An existing empty/unavailable row with a known YAML value is preserved and
  blocks pending adjudication. No safe-fill UPDATE policy was approved.
- Reviewed source conflicts retain their explicit claims. A different existing
  conflict or evidence-role conflict blocks; no silent conflict resolution.
- New unknown rows have no typed value. Known database values are not cleared
  when the source is unknown.
- Sources, device-source links and evidence identities are deterministic.
  Existing source metadata, evidence, link flags and extra sourced rows are
  preserved; the importer does not replace provenance with YAML copy.

No DELETE, DDL, migrations, ledger inserts, activation, legacy JSON replacement,
publication changes on existing devices, or grant revocations are allowed.
Do not demand 1,488 inserts: current Production previously had 24/1,488 rows.
Future reconciliation may reveal zero inserts or conflicts needing adjudication.

## Execution Lifecycle

The separately authorized executor command is:

```powershell
node scripts/qa/catalog-production-import-runner.mjs --execute-production --packet <reviewed-packet> --authorization-receipt <exact-human-approved-receipt>
```

Do NOT run this command during preparation. No arguments means NOT_AUTHORIZED
with zero connections. Activation/hardening flags are not supported.
Credentials and approved CA enter only a private in-memory child environment:
`P9_PRODUCTION_DATABASE_URL`, `P9_PRODUCTION_DATABASE_CA_CERT_PATH`.
No DSN/password in arguments, repository, artifacts or stdout. Reuse the
validated Session Pooler parser and CA parser; hostname verification and
`rejectUnauthorized=true` remain mandatory. No TLS downgrade or alternate target.

The executor validates clean checkout, exact hashes, approval and window, then
claims a durable exclusive fsynced marker under the common Git metadata before
opening its sole session. The marker is retained on every outcome; moving to a
different linked worktree cannot reuse its authorization ID.

1. One read-only repeatable-read transaction verifies identity, exact completed
   state-2 schema/ledger/legacy grants, and approved reconciliation digest.
2. Begin the only write transaction. Lock the ledger/catalog tables, recheck
   structural state and exact private snapshot before any import dispatch.
3. Apply only the missing-identity INSERT statements from the accepted frozen
   renderer, plus its NULL schema initialization. Existing identities are NOT
   redispatched: BEFORE INSERT triggers can run before ON CONFLICT DO NOTHING.
   The executor owns BEGIN/COMMIT; the approved reconciliation binds the exact
   selected write-set SHA256. Frozen canonical SQL generation remains unchanged.
4. Before commit, verify every target identity, insert delta, existing full row,
   source/evidence relationship, NULL-only metadata update, absence of activation,
   unchanged schema/grants and bounded audit delta. Only device updated_at
   housekeeping from genuinely inserted missing specs or NULL initialization
   may advance; existing facts, copy, presentation, identity, publication and
   all other metadata are preserved. A zero-missing-row reimport changes no row.
5. Only then dispatch COMMIT. On acknowledged commit, run one read-only
   repeatable-read postcheck of structural state and the same preservation
   invariants. Close the same connection; no fresh verification connection.

## Failure, Rollback And Cleanup

Any precommit failure rolls back and closes the session; no partial content or
activation is accepted. A rollback error is reported and closure is required.
Never retry the consumed authorization automatically. Any new attempt requires
new authorization and updated evidence, not reuse of the marker.

After COMMIT dispatch but without acknowledgement, report AMBIGUOUS. Do not
pretend rollback proves no commit, issue a second connection, or retry import.
Stop for a separately authorized read-only resolution/recovery decision.
Acknowledged commit with failed postcheck is COMMITTED_VERIFICATION_FAILED,
not PASS. Close failure has its own diagnostic and also cannot be PASS.
Do not delete imported facts, audit history, or restore publication automatically.
Activation is still a separately authorized future transaction.

The safe result contains counters, commit state, candidate, reconciliation
digest, insertion counts and closed diagnostics: operation, SQLSTATE, allowed
failure class, duration and connected boolean. Outer wrappers must preserve
these fields, not replace them with a generic failure or add raw error fields.
No driver message/detail/stack, rows, host/user/password fragments or CA bytes.
Close owned sessions, erase private in-memory input, remove owned private input
files under a separately approved wrapper cleanup contract, retain only safe
receipts plus durable claim. No Production private-input wrapper is opened here.
